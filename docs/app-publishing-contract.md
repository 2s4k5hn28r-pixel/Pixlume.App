# Pixlume website → GitHub → native app

## Endpoints
GET https://pixlume.app/api/news (public, no cookies or GitHub credentials).
Send If-None-Match with the previous ETag; 304 means unchanged. Poll at launch, when Home becomes active, and at most once per five minutes while active. On errors keep the last successful feed and show offline/stale status. Replace the cached collection by stable IDs on each successful full snapshot: missing items are unpublished or deleted. Never append duplicate records.

schemaVersion is 1. revision is SHA-256 of current announcements and releases. announcements have stable id, title, description, summary, bodyMarkdown, publishedAt, updatedAt, platforms, url and optional releaseVersion. releases have stable id, title, description, version, build, publishedAt, updatedAt, platforms, minimumOS, architectures, bodyMarkdown, url, downloadURL, fileName, fileSize (decimal string), sha256. latestRelease is the latest published downloadable macOS release or null. Availability is filtered by publication date, never device clock. ISO 8601 dates use UTC.

Published feeds and artifacts are intentionally public, even while the marketing website is beta locked. Drafts and future scheduled records are excluded. Publishing to the public GitHub repository makes the mirrored ZIP public too.

## Update UX contract
Compare the installed CFBundleShortVersionString and CFBundleVersion with latestRelease using numeric version segments (not lexicographic strings). Do not prompt for an older version. Honor platform and minimumOS; macOS ZIPs are not iPadOS installers. Store a per-release reminder time for Remind Me Later.

Title: A New Pixlume Update Is Available!
Update Now: open downloadURL with the system browser. This is a manual download, not a silent installation.
Remind Me Later: dismiss and persist the chosen reminder interval.
What's New: open latestRelease.url, or show its bodyMarkdown in the existing workspace.
Do not alter Sparkle. Once its existing updater is separately verified, route Update Now to its existing action instead of adding a second updater.

News is displayed inside the existing Home workspace on macOS and iPadOS; no extra floating windows. Escape content and restrict external links to HTTPS. Implement URLSession decoding, HTTP/status handling, ETag caching and cancellation. Never store GitHub tokens in the app.

## GitHub mirror
Repository: 2s4k5hn28r-pixel/Pixlume.App.
Workflow: .github/workflows/sync-website.yml. Scheduled about every five minutes (GitHub may delay scheduled jobs); also runs when this workflow or its scripts are pushed. Run workflow and rerun controls are available in GitHub Actions, linked from the existing website admin sections.
GitHub Actions GITHUB_TOKEN has Contents: write and is never sent to Pixlume. No GitHub credentials exist in client bundles or feeds. Managed releases use stable pixlume-<website-id> tags and an identity marker in their body. Version/title/date/notes edits update the same release; changing version does not create duplicates. GitHub's own published_at timestamp is generated by GitHub and cannot be backdated; the original website publication date is preserved in the release body and JSON.
ZIP assets are streamed to temporary disk, checked against SHA-256 and size, uploaded with a checksum-based name, then old managed ZIPs are removed. Other releases and assets remain untouched. Removing a website release from the public feed removes its managed GitHub release, while immutable snapshots remain under publishing/history. News edits replace publishing/news.json; missing IDs remove entries from the current mirror. Historical snapshots are intentionally retained.
A failed job retries transient HTTP/upload operations, reports failure in Actions, and retries on the next schedule. Concurrent sync jobs are serialized. Reconciliation is safe after a partial failure and does not recreate existing stable IDs.

## Native verification status
The native application source was not present in the release repository during this implementation. No native app code has been changed or compiled here. This contract defines the required app-side integration; successful website/Actions tests do not establish native connectivity.
